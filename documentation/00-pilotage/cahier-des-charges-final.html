Objectif et architecture

Plateforme universelle de communication et de coordination entre humains et agents indépendants. La messagerie transporte les contenus ; l’orchestrateur suit les tâches ; les runtimes exécutent les opérations autorisées. Aucun fournisseur de modèle unique ne doit être nécessaire.

Le service doit fonctionner sur Internet et sur un intranet isolé avec ses composants installés localement. Les documents livrés sont des HTML autonomes avec styles intégrés ; le produit possède ses ressources locales compilées et son serveur.

Critères de recette

  • Aucun bouton inactif sans explication ; chaque action valide ses entrées et expose chargement, succès ou erreur.
  • Les invitations restent explicites, et les compteurs résistent aux opérations concurrentes.
  • L’actualisation conserve la possibilité de reprise du coffre dans l’onglet ; verrouiller la retire.
  • Aucune clé privée de message ou phrase de récupération en clair dans les API métier et les journaux.
  • Les données reçues d’agents ne constituent jamais des autorisations d’exécution.
  • Les échecs réseau et délais de livraison ne déclenchent pas de duplication automatique d’un envoi.
  • Chaque exigence possède son emplacement, un test pertinent ou un contrôle manuel identifié, et un résultat daté.
  • Les essais matériels, de restauration complète et de production restent des critères distincts des tests unitaires.

Dépendances opérateur

Les identifiants WalletConnect, services cloud, domaines, certificats et autorisations de déploiement doivent être réels. Aucun identifiant fictif ne sera utilisé pour annoncer ces services fonctionnels. L’interface doit préciser leur indisponibilité tant que la configuration n’existe pas.

Glossaire

Implémenté
Le code existe ; cela ne signifie pas une qualification universelle de chaque appareil.
Qualifié par test
Une vérification identifiée a effectivement réussi dans le périmètre indiqué.
Matrix
Transport de messagerie avec chiffrement de bout en bout pour les salons privés de PolyTalk.
MCP
Interface d’outils utilisée ici en stdio avec un connecteur natif local.
A2A
Protocole entre agents ; PolyTalk possède actuellement un profil de relais local limité.
Runtime
Processus qui exécute les opérations d’un agent ; une messagerie ne suffit pas à créer un agent autonome.
