1. Périmètre et lecture

Inventaire de 120 contextes nommés : écrans, sous-vues et états transversaux. Un ID n’est pas nécessairement une URL ou une fonctionnalité déjà disponible. Les destinations sont architecturales et peuvent être remplacées par un état conditionnel de sécurité ou d’erreur.

La correspondance de code indique où une partie de la fonction existe. Elle ne certifie pas la réalisation de l’écran cible. Les composants, textes et états complets de chaque écran seront spécifiés à l’étape 4, après le design system.

Source : inventaire-ecrans.json. Régénération : node scripts/render-ux-architecture.mjs. Le script vérifie l’unicité des ID, l’existence des destinations, les références de code et la couverture F01–F42.

Cible mobile : quatre destinations nommées de premier niveau, Conversations, Contacts, Invitations et Paramètres. Agents IA est une entrée secondaire explicite depuis l’accueil. Sur grand écran, les destinations peuvent être persistantes dans une colonne. La navigation mobile actuelle n’est pas déclarée identique à cette cible : validation puis réalisation sont nécessaires.

Le logo revient à l’accueil. Retour remonte d’un niveau et restaure le contexte, sans déconnecter. Fermer annule la fenêtre ; si une saisie serait perdue, une confirmation est requise. Aucun contrôle critique n’est réservé au survol.

4. Parcours complets et erreurs

J01 — Visiteur — compte simple

Nominal : ACC01 → ACC02 → ACC13 → MSG01

Erreurs, annulation et reprise : Code facultatif absent : ne pas bloquer. Identifiant pris : conserver la saisie et permettre sa modification. Compte créé avant erreur : retrouver ce compte sans recréation implicite.

J02 — Titulaire — connexion et second facteur

Nominal : ACC01 → ACC12 si activé → MSG01

Erreurs, annulation et reprise : Mot de passe incorrect : message non révélateur. Quota : délai lisible. Code incorrect ou expiré : recommencer explicitement. Annulation : retour ACC01 et révocation de la session temporaire.

J03 — Titulaire — clé d’accès ou wallet

Nominal : ACC04 → ACC05 ou ACC06/ACC07 → ACC12 si activé → MSG01

Erreurs, annulation et reprise : Méthode absente, refusée ou expirée : revenir au choix et proposer le mot de passe. Sans Internet, l’absence de relais externe ne bloque pas les méthodes locales. Aucune transaction financière.

J04 — Nouveau compte — identité locale

Nominal : ACC04 → ACC08 → ACC09 → MSG01

Erreurs, annulation et reprise : Conserver fichier et code avant création. Association interrompue : ACC10 puis ACC11. Code invalide ou autre installation : aucun nouveau compte ni association.

J05 — Personne — nouveau contact

Nominal : MSG01 → MSG04 → invitation → MSG03

Erreurs, annulation et reprise : Adresse invalide : corriger sur place. Destinataire inconnu : aperçu prudent. Création incertaine : SYS07 et vérification des conversations avant nouvel essai.

J06 — Personne invitée

Nominal : MSG08 → MSG09 → accepter → MSG03

Erreurs, annulation et reprise : Refuser demande une confirmation et retourne aux invitations. Invitation déjà traitée : actualiser sans nouveau lot. Déchiffrement conditionné à la réception des clés.

J07 — Personne — message et fichier

Nominal : MSG03 → MSG16 si fichier → Envoyer → MSG03

Erreurs, annulation et reprise : Retrait avant envoi. Hors ligne : action indisponible. Fichier déposé puis texte échoué : réessayer seulement le texte. Changement de salon : ne pas envoyer une saisie dans un autre salon.

J08 — Personne — recherche

Nominal : MSG14 → MSG15 → MSG03

Erreurs, annulation et reprise : Zéro résultat : rappeler la portée des messages chargés. Clés absentes : SYS08 puis PAR24. Message retiré des droits : retirer le résultat et proposer une recherche actualisée.

J09 — Personne — partage et import de contact

Nominal : MSG13 → partage → MSG10 ou MSG12 → MSG11 → MSG03

Erreurs, annulation et reprise : Partage annulé : rester sur place. QR, carte ou origine invalides : erreur sans invitation. Adresse propre : expliquer et empêcher l’auto-invitation.

J10 — Personne — réception et blocage

Nominal : PAR01 → PAR03 → PAR04 → PAR03

Erreurs, annulation et reprise : Adresse invalide : garder la saisie. Politique inconnue : ne pas exposer de nouveaux contenus non autorisés. Confirmation avant blocage ; les copies déjà reçues ne disparaissent pas à distance.

J11 — Personne — sécurité facultative

Nominal : PAR01 → PAR06 → PAR07 → PAR08

Erreurs, annulation et reprise : TOTP non confirmé : rester désactivé. Code incorrect : corriger sans plusieurs inscriptions. Codes de secours : conservation explicite puis effacement à fermeture.

J12 — Personne — appareil perdu

Nominal : PAR17 → PAR18 → confirmation → PAR17

Erreurs, annulation et reprise : Exiger la preuve disponible, ne pas révoquer l’appareil courant par confusion. Appareil déjà retiré : résultat explicite. Sans preuve suffisante : aide honnête, pas de contournement.

J13 — Personne — sauvegarde et restauration

Nominal : PAR21 → PAR22 → PAR23 ; autre appareil : ACC01 → PAR24 → PAR21 → MSG03

Erreurs, annulation et reprise : Sans sauvegarde, expliquer les exports existants. Mauvais secret : ne pas remplacer la sauvegarde. Version incompatible : motif précis. Succès partiel : nombre restauré et limites, sans promettre tout l’historique.

J14 — Personne — cloud volontaire

Nominal : PAR21 → PAR30 → PAR31 → PAR32 ; restauration PAR33

Erreurs, annulation et reprise : Connecteur absent : SYS06 avant demande d’autorisation. Refus du fournisseur : aucune activation. Intranet isolé : garder les possibilités locales. Échec de copie : ne pas effacer une sauvegarde valide.

J15 — Opérateur — attribution

Nominal : AGT01 → AGT02 → AGT06 → AGT09 → AGT10

Erreurs, annulation et reprise : Agent non enregistré, absent ou bloqué : raison avant attribution. Consignes déposées mais contrat incertain : SYS07, conserver la référence et vérifier sans renvoyer.

J16 — Agent machine — exécution

Nominal : AGT11 via API/MCP → état en cours → AGT12 → résultat

Erreurs, annulation et reprise : Arrêt : rattraper les messages à la reprise. Pas de lanceur autorisé : ne pas démarrer. Expiration, annulation ou retrait de droit : refuser l’action ; une instruction reçue n’est pas une permission.

J17 — Opérateur et agent — délégation

Nominal : AGT14 → AGT13 → AGT15 → AGT16 → AGT10

Erreurs, annulation et reprise : Interdiction prioritaire. Cycle, budget, profondeur ou délai dépassé : refus serveur. Approbation expirée : nouvelle demande. Annulation propagée aux contrats, sans promesse d’arrêt arbitraire d’un processus distant.

J18 — Opérateur — supervision

Erreurs, annulation et reprise : Flux interrompu : état, reprise bornée et curseur. Saisie en cours conservée. Version dépassée : état actuel présenté avant nouvelle décision, sans transition doublée.

Erreurs, annulation et reprise : Espace privé non autorisé : refus. Version modifiée : comparaison avant écrasement. Procédure non fiable : examen avant utilisation ; son texte ne confère aucun droit.

J20 — Opérateur — équipe réutilisable

Erreurs, annulation et reprise : Origine, champs ou doublons invalides : pas d’invitation. Identité échouée : aucun groupe créé. Réponse incertaine : verrou de répétition et SYS07.

J21 — Propriétaire — connecteur et moteur

6. Retour contextuel contrôlé

Le jeton @context est une règle de navigation, pas une route libre. Il est lié au compte, à la génération de session et au parcours appelants. Il contient uniquement une destination interne nommée ; jamais une URL, un script ou un secret.

Avant retour, vérifier session, rôle et droit sur la ressource. Conserver la saisie non sensible seulement dans le même contexte autorisé. Si le contexte disparaît mais que la session reste valide, revenir à MSG01. Si la session expire ou est révoquée, effacer les vues privées et le moyen de reprise puis revenir à ACC01. SYS03 ne permet aucune sortie directe vers un espace privé.

Annuler ne déclenche ni mutation ni répétition. Une création incertaine reste verrouillée jusqu’à vérification de son identifiant et de son état. Abandonner une saisie requiert sa confirmation et rejoint la destination demandée validée, sans conserver le secret saisi.

7. Administration et interfaces externes

L’administrateur ne récupère pas les clés des utilisateurs. Les procédures documentées couvrent inscription, origine, rôles opérateurs, quotas, secrets d’infrastructure, TLS, conteneurs, sauvegarde serveur, distribution intranet, diagnostic, mise à jour et retour arrière. Aucune console universelle lisant les conversations n’est ajoutée.

WebAuthn, wallets, sélecteurs de fichiers, partage natif et notifications sont des frontières de parcours. PolyTalk explique le résultat attendu et gère annulation, refus ou absence de support ; l’aspect exact reste celui du système tiers.

L’agent machine utilise un connecteur réellement présent, sans devoir cliquer dans une interface humaine. SLIM/MLS restent des pistes à valider ; ils ne sont pas une case activant un chiffrement opérationnel dans l’application actuelle.
