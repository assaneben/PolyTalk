Design system et contrats des composants

Référentiel pour les interfaces humaines et la supervision des agents.

Architecture autorisée le 20 octobre. Ce document définit les règles du design system. Il ne déclare pas les 120 contextes déjà implémentés ni validés visuellement. Les écarts au code restent suivis dans le plan QA.

Principes et navigation

La personne humaine commence dans Conversations. Les fonctions courantes portent des verbes : Nouvelle conversation, Trouver un contact, Notifications et invitations, Mon adresse et QR code, Paramètres. La coordination des agents reste une entrée explicite ; aucune action de chat ne lance implicitement un programme.

Une action principale par étape ; les options de sécurité supplémentaires restent facultatives. Objectif de navigation : 1 action pour ouvrir une conversation connue, 2 pour afficher son adresse ou ses invitations, au plus 3 pour une rubrique courante de paramètres. Ces seuils doivent être mesurés dans les écrans détaillés et la recette.

Typographie et dimensions

Police système : system-ui, -apple-system, BlinkMacSystemFont, Segoe UI, sans-serif. Aucune police distante. Corps cible 16 px, interligne 1,6 ; aide 14 px, interligne 1,5 ; titre de page 28 px/1,25 ; titre de rubrique 22 px/1,3 ; sous-titre 18 px/1,4. Graisse 400 pour le contenu, 600 pour les labels et actions, 700 pour les titres. Les identifiants techniques utilisent ui-monospace avec retour à la ligne.

Espacement : 4, 8, 12, 16, 24, 32 et 48 px. Petit groupe : 8 px ; label/champ : 8 px ; champs successifs : 16 px ; rubriques : 24 px ; marge de page mobile : 16 px ; grand écran : 24 px. Rayon : 10 px pour champ et bouton, 12 px pour carte, 16 px pour grande fenêtre. Une ombre ne remplace pas une bordure lisible.

Cible tactile minimale 44 × 44 CSS px et espace recommandé de 8 px entre actions distinctes. Il s’agit de l’exigence du projet, plus stricte que le minimum WCAG 2.2 AA de 24 px avec exceptions. Icône 20–24 px à l’intérieur de la cible ; texte visible pour toute action ambiguë.

22 composants et comportements

C01 · Action principale

Textes : Créer mon compte ; Se connecter ; Envoyer ; Enregistrer mon nom.

Structure et action : Une seule action principale par écran. Déclencher la soumission du formulaire associé après validation. Hauteur minimale 44 px, largeur complète sur mobile si l’action termine une étape.

États spécifiques : Chargement : conserver le libellé, ajouter « En cours… », aria-busy et verrou anti-double clic. Désactivé : expliquer ce qui manque avant le bouton. Erreur : restituer la saisie autorisée et afficher la cause. Succès : texte spécifique à l’opération, sans nouvelle soumission.

C02 · Action secondaire

Textes : Annuler ; Revenir aux paramètres ; Vérifier la création précédente.

Structure et action : Ne déclencher aucune mutation lors d’une annulation. Pour une création incertaine, rechercher la référence existante au lieu de renvoyer une invitation.

États spécifiques : Indisponible : indiquer la raison. Échec de vérification : « Création encore indéterminée. Attendez la synchronisation puis vérifiez à nouveau. » Aucun faux succès.

C03 · Action destructive

Textes : Refuser cette invitation ; Révoquer cette session ; Retirer cette clé de connexion.

Structure et action : Ouvrir une confirmation nommant la cible et l’effet exact. Annuler reçoit le focus initial. La validation s’applique à la cible sélectionnée et à la même génération de session.

États spécifiques : Confirmation annulée : aucune requête. Envoi : verrouiller les deux actions. Échec : afficher la cause et garder une issue. Succès : retirer uniquement la cible confirmée ; ne pas annoncer l’effacement des copies distantes.

C04 · Champ texte

Textes : Adresse de votre contact ; Nom affiché ; Nom du groupe (facultatif).

Structure et action : Label visible permanent ; aide sous le champ. Le placeholder donne un exemple, jamais le seul label. Associer aide et erreur par aria-describedby. Utiliser inputmode adapté.

États spécifiques : Vide : aide de saisie. Invalide : aria-invalid et message précis. Focus : contour visible. Lecture seule : valeur sélectionnable. Envoi : empêcher les modifications pouvant changer la cible en cours.

C05 · Mot de passe et phrase

Textes : Mot de passe ; Phrase de restauration facultative ; Confirmer la phrase de restauration.

Structure et action : Distinguer connexion, coffre local, phrase de restauration et fichier exporté. Permettre le collage et les gestionnaires. Afficher/masquer conserve valeur, curseur et focus ; aria-pressed indique la visibilité.

États spécifiques : Erreur de connexion : « Identifiant ou mot de passe incorrect. » Ne révéler ni existence de compte ni secret. Fermer une vue efface ses secrets. Un secret n’est jamais affiché dans une notification.

C06 · Champ code

Textes : Code TOTP ou code de secours ; Code d’invitation (facultatif).

Structure et action : Préciser pourquoi le code est demandé. TOTP : code à six chiffres ; code de secours : format complet accepté. Code d’invitation exigé uniquement si la configuration de l’installation l’impose.

États spécifiques : Code vide quand requis : « Saisissez votre code. » Code refusé : « Code invalide ou expiré. Réessayez avec le code actuel. » Limitation : afficher le délai reçu du serveur sans soumettre automatiquement.

C07 · Case à cocher

Textes : J’ai conservé mon code de récupération.

Structure et action : Label cliquable sur une zone d’au moins 44 px ; état lisible avec coche et texte. Activation des sauvegardes et protections toujours volontaire, jamais pré-cochée par défaut.

États spécifiques : Inactif : décrire la conséquence. Erreur : message associé au groupe. Une case seule ne déclenche aucune suppression.

C08 · Choix exclusif

Textes : Manuel — agents mentionnés ; Agent principal ; Tous les agents.

Structure et action : Présenter les modes avec leur description. Choisir le mode ne lui donne aucun droit d’exécution ; Enregistrer applique explicitement le choix.

États spécifiques : Sans agent principal sélectionné : expliquer ce qui manque et refuser l’enregistrement. Version concurrente : actualiser avant de recommencer.

C09 · Interrupteur de préférence

Textes : M’avertir sur cet appareil.

Structure et action : Afficher Activé ou Désactivé en texte. Demander la permission système au clic explicite. Ne pas annoncer une activation avant le résultat du navigateur.

États spécifiques : Permission refusée : « Notifications refusées par le navigateur. Vous pouvez modifier ce choix dans ses paramètres. » Fonction absente : aide adaptée ; les invitations restent consultables dans l’application.

C10 · Carte de réglage

Textes : Mon profil ; Qui peut me contacter ; Connexion et sécurité ; Sauvegarder mes conversations ; Mes appareils.

Structure et action : Titre d’action explicite, description et destination unique. La carte ne contient pas de boutons imbriqués. Retour « Tous les paramètres » toujours présent dans une sous-rubrique.

États spécifiques : Chargement de rubrique : titre stable et statut annoncé. Vide : texte utile, action correspondante. Erreur : Réessayer et retour aux paramètres, sans écran bloqué.

C11 · Liste de conversations

Textes : Conversations ; Invitations reçues ; Conversations non lues.

Structure et action : Nom, type humain/agent si connu, dernier événement autorisé, date et nombre non lu. Le clic ouvre la conversation sélectionnée ; l’espace clavier active la ligne si c’est un bouton.

États spécifiques : Vide : « Aucune conversation. Créez une conversation ou partagez votre adresse. » Reconnexion : garder la liste autorisée et signaler l’état ; session expirée : effacer les vues privées.

C12 · Invitation

Textes : Invitation de @contact:serveur ; Consulter ; Accepter ; Refuser.

Structure et action : Aucune acceptation automatique. Consulter ouvre les informations sans rejoindre. Accepter vérifie l’invitation courante avant join ; Refuser exige confirmation avant leave.

États spécifiques : Invitation déjà traitée : « Cette invitation n’est plus en attente. » Fenêtre fermée pendant attente : ne pas ouvrir une conversation après coup. Nombre d’invitations indépendant du nombre de messages non lus.

C13 · Message

Textes : Envoyer ; Retirer le fichier.

Structure et action : Associer auteur, heure, contenu et état de remise. Entrée envoie hors composition IME ; Maj+Entrée ajoute une ligne. Aucun contenu n’est envoyé avant le contrôle de chiffrement et de permission.

États spécifiques : Vide : Envoyer désactivé. Envoi : bloquer un second envoi identique. Hors ligne : conserver le brouillon dans la portée documentée et expliquer la reprise. Erreur : ne pas vider un texte non envoyé.

C14 · Pièce jointe

Textes : Ajouter un fichier ; Prêt à envoyer ; Retirer le fichier.

Structure et action : Nom, taille et limite lisibles. Le sélecteur annule sans envoyer. Afficher clairement si le fichier est préparé, en cours ou envoyé.

États spécifiques : Trop volumineux : « Fichier trop volumineux : 10 Mio maximum. » Erreur de chiffrement : ne pas envoyer en clair. La suppression d’un fichier préparé ne supprime pas un message déjà envoyé.

C15 · Adresse, lien et QR code

Textes : Mon adresse PolyTalk ; Copier mon adresse ; Partager….

Structure et action : Afficher l’adresse textuelle à côté du QR. Copier fournit un retour explicite. Si le partage natif manque, proposer la copie. Le logo ramène à l’accueil correspondant à la session courante.

États spécifiques : Copie refusée : valeur sélectionnable et instruction de copie manuelle. Contact modifié : effacer l’aperçu et demander une nouvelle vérification avant toute invitation.

C16 · Recherche et pagination

Textes : Rechercher dans les messages disponibles ; Page suivante des tâches ; Revenir au début des tâches.

Structure et action : Préciser la portée réelle de la recherche. Une page vide après filtrage peut encore proposer une page suivante. Retour à la conversation cible et mise en évidence du résultat si présent.

États spécifiques : Aucun résultat : afficher les critères actifs et l’action pour les effacer. Résultat disparu : expliquer son indisponibilité. Curseur invalide : revenir au début sans élargir les permissions.

C17 · Fenêtre modale

Textes : Titre de l’action ; Fermer ; Annuler.

Structure et action : Une fenêtre active, titre lié par aria-labelledby, focus placé sur le premier contenu utile ; focus piégé nativement et rendu au déclencheur à la fermeture. Échap annule ; une saisie abandonnée demande confirmation.

États spécifiques : Ouverture : annoncer le titre. Chargement : garder une sortie. Erreur : message dans la fenêtre. Fermeture ou remplacement : détacher écouteurs et annuler les travaux annulables ; aucune mutation retardée non autorisée.

C18 · Notification temporaire

Textes : Nom enregistré ; Invitation refusée ; Conversation retrouvée.

Structure et action : role=status pour un succès non urgent, aria-live=polite. Une erreur bloquante reste aussi dans la vue concernée ; le toast ne doit pas être son unique emplacement.

États spécifiques : Succès : description de l’effet réel. Erreur : prochaine action explicite. Ne jamais y inclure mot de passe, jeton, phrase ou code de récupération. Éviter les successions effaçant une erreur avant lecture.

C19 · État global de connexion

Textes : Connexion… ; Synchronisation… ; Connecté ; Hors ligne ; Verrouillé.

Structure et action : Associer texte, symbole et couleur. Une erreur réseau ne supprime pas le coffre. Un 401 authentifié courant verrouille le client, efface la vue privée et ramène à la connexion.

États spécifiques : 401 ancien : ignorer pour la session nouvelle. 403 : expliquer le refus de cette action sans promettre un envoi. 503 : maintenir les protections et proposer la reconnexion. Ne pas activer Envoyer avant chiffrement prêt.

C20 · Tâche et approbation

Textes : Accepter et démarrer ; Demander une validation ; Terminer avec un résultat chiffré ; Annuler.

Structure et action : Responsable, destinataire, état, version et échéance. Seules les transitions autorisées sont proposées. La consultation d’un message ne vaut pas droit d’exécuter un outil.

États spécifiques : Version concurrente : recharger le contrat. Expirée ou annulée : interdire une nouvelle exécution. Terminer exige une référence de résultat chiffré. Une annulation de contrat ne promet pas l’arrêt d’un processus distant.

C21 · Code de récupération

Textes : Préparer mon code de récupération ; Enregistrer mon code dans un fichier ; J’ai conservé mon code.

Structure et action : Présenter le secret seulement dans la vue prévue, sans télémétrie ni toast. Expliquer que le fichier contient un secret. Proposer la phrase de restauration comme option distincte du mot de passe.

États spécifiques : Activation non confirmée : conserver le code déjà sauvegardé et vérifier l’état. Rotation : conserver l’ancienne version avant la copie. Suppression : confirmation explicite et périmètre exact. Vue fermée : effacer les champs.

C22 · Clé d’accès et wallet

Textes : Ajouter une passkey ou une clé USB/NFC ; Se connecter avec un wallet.

Structure et action : Expliquer le dialogue système avant ouverture et laisser choisir un autre moyen. Le wallet signe une preuve de connexion, sans paiement ni transfert. Ledger dépend du wallet et du navigateur effectivement compatibles.

États spécifiques : Annulation système : retour neutre, sans création partielle. Compte wallet changé : recommencer la preuve. Project ID absent : signaler l’indisponibilité du QR et conserver identifiant/mot de passe ; aucune fausse session.

États et interactions

ÉtatRègle commune
NormalAction lisible, cible et conséquences compréhensibles avant activation.
ChargementRetour immédiat au clic ; texte En cours… et aria-busy. Bloquer les répétitions mais garder une sortie lorsque la requête est annulable. Ne pas afficher un succès avant la réponse.
VideExpliquer ce qui manque et proposer une action réalisable ; aucun contenu de démonstration présenté comme réel.
ErreurMessage près de l’action ou du champ, cause compréhensible, moyen de réessayer ou de revenir. Une erreur réseau ne devient pas une déconnexion systématique.
SuccèsNommer l’effet obtenu, conserver les limites : envoyé n’est pas lu, contrat annulé n’est pas processus arrêté.
DésactivéNe pas utiliser la couleur seule. Donner la condition d’activation dans une aide visible ; conserver un contraste lisible du libellé explicatif.
SurvolVariation de fond et soulignement pour le lien ; aucune fonction uniquement disponible au survol.
Appui / focusRetour de pression sans déplacement de la mise en page ; contour clavier visible et ordre logique. Le focus n’active jamais une action destructive.

Transitions : 120–180 ms pour fond et opacité ; aucune animation du contenu d’un message pour retarder son accessibilité. Respecter prefers-reduced-motion : supprimer les mouvements non essentiels. Les erreurs et demandes d’approbation ne disparaissent pas par une animation automatique. Le délai d’un toast ne remplace pas une confirmation durable d’une opération critique.

Accessibilité et adaptation

Mobile : une colonne, navigation de conversation conservant un retour explicite. Tablette : liste et conversation lorsque la largeur le permet. Ordinateur : navigation latérale, liste et conversation sans imposer une taille minimale de fenêtre. Les réglages deviennent une surface pleine largeur sur petit écran, avec titre et fermeture accessibles au pouce. À 320 CSS px, aucun défilement horizontal du texte courant ; les tableaux techniques disposent de leur propre zone de défilement nommée.

Zoom 200 % et 400 %, clavier seul, lecteur d’écran, mode contraste élevé et orientation portrait/paysage doivent être testés. Langue fr, liens explicites, ordre des titres cohérent, libellés associés aux champs, messages de statut annoncés. Une icône décorative est aria-hidden ; une action conserve son nom accessible. La notification native et l’authentificateur restent des interfaces du système, dont la disponibilité est détectée.

Maintenance et validation

Tokens actuels : web/style.css ; boutons et champs communs : web/app.js ; cycle des fenêtres : web/private-view.js ; contrôles d’action : web/ui-actions.js ; état de session : web/matrix-client.js ; notifications : web/notifications-ui.js. L’échelle typographique cible ci-dessus demande encore un alignement du code courant, dont la base est de 15 px. Aucun alignement n’est supposé déjà réalisé par la publication de ce document.

Pour chaque contexte de inventaire-ecrans.json, les écrans détaillés doivent référencer C01–C22, décrire les huit états et définir l’entrée, la sortie, les erreurs et la portée de persistance. La checklist doit ensuite lier chaque exigence à une preuve de code, un test et, si nécessaire, une recette visuelle. Le plan QA reste ouvert pour les comportements non implémentés, notamment les saisies abandonnées et les qualifications multi-appareils.

Contrôles de ce document : palette calculée, document autonome et libellés réels. Validation visuelle de l’application : non réalisée par ce document.

Glossaire

Token
Valeur nommée de couleur, taille ou espacement réutilisée par les composants.
Focus
Élément actuellement ciblé par le clavier ou une technologie d’assistance.
État indéterminé
Requête dont la réussite ne peut pas être confirmée ; ne pas répéter automatiquement une mutation.
Clé de récupération
Secret ouvrant une sauvegarde donnée ; ne remplace pas un mot de passe de connexion.
Recette visuelle
Vérification réelle des dimensions, contrastes, interactions et aides sur un appareil cible.
