Modifier la conception

  1. Identifier les exigences et les ID d’écran affectés. Ne pas renuméroter un écran existant pour en réutiliser l’identifiant.
  2. Modifier les entrées, sorties, états d’erreur et règles de retour. Une destination contextuelle est liée à la session et n’est jamais une URL libre.
  3. Indiquer l’écart avec le code : surface existante, couverture partielle ou écran cible absent.
  4. Mettre à jour le JSON puis les textes du générateur. Ne pas modifier directement les deux HTML générés.
  5. Régénérer et vérifier les fichiers : 
    node scripts/render-ux-architecture.mjs
    Le script contrôle unicité des ID, destinations internes, références de code et couverture F01–F42.
  6. Vérifier les sommaires, ancres, liens, glossaires et autonomie HTML, sans police ou bibliothèque distante.

La méthode de conception possède un point d’accord explicite entre architecture et design system. Une correction documentaire de l’architecture n’autorise pas à démarrer automatiquement l’étape suivante.

Modifier l’application

  1. Partir du parcours approuvé et recenser données sensibles, droits, erreurs et variantes.
  2. Écrire une régression pertinente pour un changement de comportement ; vérifier qu’elle reproduit le défaut.
  3. Modifier les composants concernés et préserver les liaisons DOM ou les adapter avec leurs tests.
  4. Exécuter, successivement : 
    npm test
npm run build
npm run doctor
  5. Choisir les intégrations Matrix, MCP, A2A ou Rust pertinentes ; utiliser exclusivement des comptes et fixtures QA autorisés.
  6. Ne pas assimiler la compilation à la disponibilité de tous les protocoles ou matériels.

Pour la navigation humaine : human-guidance.js. Pour les paramètres : settings-ui.js. Pour les fichiers en attente : prepared-message.js. Les tests correspondants portent des noms proches dans tests/.

Faire la recette d’un écran

  • Normal : objectif, action principale et navigation compréhensibles.
  • Chargement : retour immédiat, progression et doubles actions empêchées.
  • Vide et erreur : explication, données conservées et reprise réelle.
  • Succès : effet exact, sans confondre dépôt, lecture et résultat.
  • Désactivé : condition d’accès expliquée.
  • Survol, appui, focus et clavier : fonctionnement cohérent, pas de contrôle exclusif au survol.
  • Annulation : pas de mutation ou secret conservé silencieusement.
  • Résultat incertain : vérifier avant de répéter.
  • Téléphone, tablette, ordinateur, portrait/paysage, zoom et lecteur d’écran : recette dans un environnement autorisé.
  • Contrastes : mesurer les couples de couleurs réellement utilisés et vérifier le rendu. Ne pas déclarer WCAG AA par le seul choix d’une palette.

Le refus antérieur d’accès visuel n’a pas été contourné. Une recette visuelle nécessite un accès autorisé ; les tests unitaires ne la remplacent pas.

Actualiser la progression

  1. Début de lot : objectif et statut.
  2. Pendant le lot : résultat utile ou blocage réel.
  3. Fin : fichiers, commandes exécutées, résultats, limites et prochaine condition.
  4. Mettre à jour le TODO, la matrice, le rapport et le README si leurs informations changent.

Dernier socle web observé : 219 tests Node réussis et diagnostic 4/4 au lot 4b98175. Une livraison documentaire ne constitue pas une nouvelle exécution de ces tests. Aucun pourcentage arbitraire d’achèvement global n’est utilisé.

Exploitation et données privées

Le README et le guide d’administration décrivent les commandes d’installation, les profils réseau et les limites de distribution. Ne pas modifier le nom Matrix permanent ou les volumes sans plan de migration et sauvegarde.

Ne pas intégrer de mot de passe, jeton, code de secours, clé privée, fichier .env ou conversation privée dans les captures, livrables et exemples. Les diagnostics destinés au support sont non sensibles. La restauration serveur ne recrée pas les clés perdues des clients.

Le build Windows optimisé reste une qualification distincte ; les protections Windows ne doivent pas être désactivées pour déclarer une livraison. Les connecteurs externes nécessitent leurs configurations réelles.

Glossaire

Source unique
Fichier faisant autorité pour une information ; les documents dérivés sont régénérés.
Preuve
Résultat observé, rattaché à une commande, une date et un périmètre.
Régression
Test reproduisant un comportement indésirable pour vérifier sa correction.
Recette
Vérification du parcours réel et de ses états dans un contexte identifié.
