Installation locale

Prérequis : Node.js 24 ou ultérieur, npm, Docker avec moteur Linux ; Rust 1.99.1 pour le connecteur natif. Préparer la configuration avec npm run setup, démarrer les services Docker du projet, construire avec npm run build, puis démarrer le serveur avec npm start. Le fichier .env contient des secrets et ne doit pas être publié.

Les profils Internet et intranet sont distincts. Une installation sans Internet utilise les images et fichiers exportés auparavant. L’export hors ligne n’inclut pas les conversations, secrets ni bases existantes et n’est pas une sauvegarde.

Inscription et opérateurs

L’inscription est ouverte par défaut. Pour une installation privée, configurer le mode invitation avec npm run setup -- --signup-mode invitation. Pour revenir au mode ouvert : npm run setup -- --signup-mode open. Conserver les clés existantes ; ne pas régénérer les secrets d’une installation qui contient des données.

Les pouvoirs d’approbation viennent des opérateurs explicitement configurés, jamais du libellé humain/agent d’un compte. Les règles Matrix de salon et de réception s’appliquent aussi aux clients tiers.

Diagnostics et vérifications

  • npm run doctor : versions, configuration présente, empreintes web et disponibilité API/Matrix, sans affichage des secrets.
  • npm run verify : tests Node, construction web et diagnostic.
  • npm run verify:runtime : ajoute tests/compilation Rust puis essais réels MCP et A2A avec la fixture de qualification.
  • npm run verify:release : exige le binaire optimisé puis teste ce binaire. Un refus de compilation arrête la qualification.

Les essais réels demandent les fixtures de test préparées et les services actifs ; ils ne doivent pas employer les comptes personnels des utilisateurs. Les résultats ne remplacent pas les essais visuels, matériels, de charge ni de TLS.

API et connecteurs

Le contrat OpenAPI 3.1 est servi sur /api/openapi.json. L’API métier utilise les sessions Matrix vérifiées. Les contenus des messages passent par l’API Matrix et son chiffrement.

MCP utilise le transport stdio et le connecteur natif. Chaque agent a son magasin et une phrase fournie par son lanceur. Le relais A2A est local, authentifié et fixé à un seul salon ; il ne constitue pas une passerelle A2A complète.

Le runtime Rust persiste sa session et ses clés dans un magasin chiffré. Ne pas supprimer ce magasin ni réutiliser son identité avec un nouveau magasin vide. Les clés de messages sont distinctes des wallets de connexion.

Sauvegardes et disponibilité

Sauvegarder les bases de contrôle, données Matrix/PostgreSQL, magasins des agents et secrets de configuration par un processus cohérent, avec essai de restauration. La sauvegarde Matrix des clés de conversation ne remplace pas ces sauvegardes d’exploitation.

Ne pas confondre arrêt Docker, serveur Node indisponible, quota de connexion et défaut de code. Un diagnostic en échec interdit d’annoncer le service prêt. Les répertoires temporaires Docker ont été mis en quarantaine lors du correctif local de sockets ; les volumes n’ont pas été supprimés.

Portes de production

Restent à qualifier : interface et reprise sur navigateurs physiques, wallets et clés matérielles, vrais paramètres WalletConnect, TLS et exposition réseau, restaurations complètes, charge, build release Windows et revue indépendante complète. Le poste actuel a déjà refusé des scripts du build release avec l’erreur 4551 ; les contrôles Windows ne doivent pas être désactivés pour masquer ce refus.

SLIM, MLS, sauvegardes cloud externes, routines, webhooks et routage intelligent restent dans la matrice des exigences tant que leur code et leurs tests ne sont pas livrés.

Glossaire

Fixture
Compte et magasin réservés à une qualification reproductible.
OpenAPI
Contrat lisible par les outils pour décrire les routes HTTP.
Release
Binaire optimisé destiné à la distribution, distinct du build de développement.
Readiness
État disponible du service, distinct d’une qualification complète de production.
