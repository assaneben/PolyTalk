1. Profils de déploiement

Le fichier commun décrit Synapse et PostgreSQL. Le profil intranet ajoute le serveur PolyTalk dans un conteneur non root, avec racine en lecture seule, capacités retirées, espace temporaire borné et volume de données dédié. Son réseau interne empêche les sorties Internet. Le profil Internet superposé permet les sorties réseau, conserve les services de données internes et exige une entrée HTTPS administrée séparément.

Les ports applicatifs publiés restent sur le loopback de l’hôte pour le reverse proxy. Aucune fédération Matrix ni publication de domaine n’est activée automatiquement. Une copie initialisée de la configuration privée donne à Synapse les droits POSIX nécessaires sans rendre les secrets publics.

TRUSTED_PROXY_PEERS accepte au maximum 16 adresses IP exactes. Pour ces seuls pairs, une adresse client unique et valide dans X-Forwarded-For sert aux quotas. Les chaînes sont refusées ; les en-têtes des autres pairs sont ignorés. Le proxy doit remplacer l’en-tête entrant, et non le transmettre ou lui ajouter une valeur.

2. Paquet hors ligne

npm run export:offline crée un nouveau dossier sous .local/releases. L’export exige que les images soient déjà disponibles localement ; il ne les télécharge pas. Les images sont archivées et reçoivent des tags propres au paquet, dérivés de leurs identifiants. Le manifeste enregistre l’architecture, l’identité et les sommes SHA-256 des fichiers.

La liste des fichiers copiés est fermée : profils Compose publics, module de contrôle Synapse, scripts de préparation et de vérification, guide README et archive d’images. Le paquet n’inclut pas le fichier .env existant, les bases, les clés, les sessions ou les conversations. Il prépare une nouvelle installation et ne remplace pas une sauvegarde ni une migration.

Les checksums détectent une modification, sans constituer une signature d’éditeur. Le paquet et un exemplaire du manifeste doivent provenir de canaux de confiance. La vérification refuse les chemins inattendus, doublons, liens symboliques, tailles ou empreintes différentes.

3. Nouvelle installation

Prérequis : Docker avec moteur Linux compatible avec les images du paquet, Node 24 pour les scripts, un DNS interne ou public et un certificat TLS approuvé par les appareils. Les exemples de noms doivent être remplacés par les noms réels avant l’initialisation.

node scripts/verify-offline.mjs
docker image load --input images.tar
node scripts/setup.mjs --container --origin https://messagerie.exemple.internal --server-name messagerie.exemple.internal

La préparation choisit les noms lors de la création, conserve les clés existantes et refuse un changement silencieux de nom Matrix ou d’origine lors d’une relance avec des valeurs différentes. Déclarer les comptes opérateurs dans le nouveau .env privé.

docker compose --env-file .env -f deploy/compose.yaml -f deploy/compose.intranet.yaml -f deploy/compose.images.yaml config --quiet
docker compose --env-file .env -f deploy/compose.yaml -f deploy/compose.intranet.yaml -f deploy/compose.images.yaml up -d --no-build --pull never

Pour Internet, ajouter le profil Internet avant le fichier de correspondance des images. Une installation intranet n’a pas besoin d’accès Internet pour ses échanges locaux, mais les appareils ont besoin d’accéder au serveur local pour envoyer et recevoir de nouveaux messages.

4. Validation observée

  • Image construite depuis des versions et digests épinglés ; import du serveur et présence de tous les chunks web vérifiés dans un conteneur sans réseau.
  • Profils Compose validés sans exposer leurs secrets.
  • Essai réel d’une pile séparée : réseau interne, aucun port publié, nouveaux volumes de test, inscription et sessions de deux comptes, échange déchiffré entre SDK Matrix, ciphertext vérifié côté serveur et refus après blocage. Premier passage réussi en 23,80 secondes.
  • La première tentative a révélé une liste YAML incorrecte pour le montage temporaire ; correction appliquée et essai rejoué avec succès.
  • Le healthcheck a aussi été vérifié après arrêt de Synapse : il refuse désormais de déclarer la pile prête.
  • Suite Node : 123 tests passants au dernier contrôle ; suite Rust : 14 tests passants. Les essais SDK MCP réels couvrent aussi les tâches et la mémoire privée du connecteur.

5. Portes de production encore ouvertes

  • Revue indépendante globale réalisée : quatre défauts importants et un défaut mineur, corrigés dans le code avec régressions ; compilation native optimisée encore bloquée par le contrôle d’application Windows (erreur 4551), sans modification des protections.
  • Qualification visuelle, clavier et lecteur d’écran des écrans ; essais physiques Windows, macOS, Linux, Android et iOS/iPadOS.
  • Installation réelle avec DNS et TLS internes approuvés, stratégie de sauvegarde/restauration et exploitation de l’organisation.
  • Project ID WalletConnect réel et essais du relais, de MetaMask et d’un Ledger physique.
  • Compatibilité A2A limitée à un relais local ; SLIM/MLS, routage automatique, automatisations avancées et environnements d’exécution optionnels restent des évolutions distinctes.

Ces validations ne sont pas remplacées par une compilation ni par un test HTTP. La présence d’un agent reflète sa connexion récente, sans certifier son moteur ni ses capacités. Les agents privés doivent appliquer leurs propres permissions d’exécution.

6. Glossaire

Intranet
Réseau local pouvant fonctionner sans Internet, avec accès à un serveur commun.
Digest
Identifiant cryptographique d’un contenu d’image.
Reverse proxy
Entrée HTTPS relayant les requêtes vers le service interne.
Volume
Stockage persistant séparé du conteneur applicatif.
Manifeste
Inventaire des fichiers et images transférés.
Qualification
Essai dans des conditions identifiées, distinct de la seule présence du code.
