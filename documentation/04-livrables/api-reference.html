Référence API HTTP Polytalk

API du registre, des politiques et des accusés. Les conversations chiffrées restent transportées par Matrix ; ces routes ne conservent aucun corps de message.

Validation de cette étape : serveur HTTP local et SQLite réels, transport Matrix externe remplacé par un double contrôlé. Ces tests contractuels ne prouvent pas un échange Matrix ou E2EE réel.

Authentification · Routes · Accusés · Service interne · Erreurs · Configuration

Authentification et formats

Les routes du registre exigent Authorization: Bearer <jeton Matrix>. Le serveur vérifie le jeton auprès de /_matrix/client/v3/account/whoami à chaque requête. Le compte doit appartenir au serveur Matrix configuré. L’identité permanente est créée lors de la première authentification réussie ; le propriétaire d’une politique ou d’un accusé provient toujours de cette authentification.

Les exceptions publiques sont GET /api/config, GET /api/health et POST /api/register. Le service interne utilise un secret distinct. Un en-tête Origin présent doit correspondre exactement à l’origine publique configurée. Les appels locaux de connecteurs peuvent omettre cet en-tête.

Les écritures Polytalk utilisent Content-Type: application/json et un objet JSON, avec un corps maximal de 65 536 octets. Les attributs sans effet, dont owner, ne permettent jamais de choisir un autre propriétaire. Les réponses de l’API ont le type JSON et Cache-Control: no-store.

Un MXID occupe au plus 255 octets UTF-8. Les identités historiques renvoyées par Matrix, dont les parties locales avec majuscules, signes plus ou barres obliques, sont acceptées sans modification. Les noms de serveurs DNS, IPv4 et IPv6 entre crochets peuvent inclure un port. Les contraintes de création de nouveaux comptes sont plus étroites.

Accusés liés à un événement accessible

{
  "roomId": "!salon:serveur.example",
  "eventId": "$identifiant-evenement",
  "state": "received"
}

roomId est obligatoire et commence par !, avec un serveur après :. eventId commence par $. Chaque identifiant a au plus 255 caractères et ne contient ni espaces ni caractères de contrôle. Les états sont received, notified et processed, dans cet ordre croissant. Une répétition ou un état antérieur ne fait pas reculer l’accusé.

Avant chaque écriture, le serveur récupère /_matrix/client/v3/rooms/{roomId}/event/{eventId} avec le jeton du demandeur. Matrix doit autoriser cet accès et retourner les mêmes identifiants de salon et d’événement. Un refus ou une absence d’événement donne 403 ; une réponse incohérente donne 502. Aucune de ces erreurs n’écrit d’accusé. Ce contrôle prouve l’accès Matrix à l’événement, pas la véracité du traitement déclaré par le client.

Le registre conserve uniquement le propriétaire, l’identifiant d’événement, l’état et la date UTC. La présence du contenu de l’événement dans la réponse Matrix ne provoque aucune persistance de ce contenu.

Évaluation interne des politiques

POST /internal/evaluate exige X-Polytalk-Policy-Secret, secret propre à l’installation, et un objet {sender, recipients}. Les valeurs sont des MXID valides ; le tableau contient au plus 1 000 destinataires.

Réponse 200 : {allowed: true|false}. Tous les destinataires doivent accepter l’expéditeur. En cas de panne de ce service, le composant Synapse appelant doit refuser les opérations protégées. L’authentification Matrix seule ne donne aucun accès à cette route. Le déploiement doit réserver le service interne à ses composants de confiance.

Erreurs et quotas

Les erreurs produites par Polytalk ont la forme {"error":"message en français"}. Les réponses du proxy Matrix conservent le statut et le format Matrix de l’amont, sauf incident de transport ou redirection refusée.

StatutSignification
400JSON non objet ou mal formé, champ invalide, identité ou état invalide.
401Jeton absent, format d’autorisation invalide ou session Matrix expirée.
403Origine refusée, compte externe à l’installation, code d’inscription ou secret interne incorrect, accès à l’événement refusé.
404Route, contact ou fichier absent ; chemin Matrix refusé.
405Méthode non autorisée sur une ressource statique.
413Corps API supérieur à 64 Kio, ou corps proxy supérieur à 12 Mio.
415Content-Type JSON absent ou incorrect sur une écriture Polytalk.
429Quota local ou Matrix dépassé.
500Erreur interne ; réponse générique sans SQL, chemin de fichier ni pile d’exécution.
502Échec Matrix non assimilable à une session expirée ou un quota ; réponse JSON ou identité amont incohérente.
503Transport Matrix indisponible, redirection interdite ou inscription non configurée.

Quotas locaux en mémoire : 90 requêtes par minute et adresse de connexion directe ; cinq tentatives d’inscription et cinq appels à un chemin Matrix finissant par /login par minute. Le redémarrage remet ces compteurs à zéro. Derrière un reverse proxy, l’adresse observée est celle du proxy : qualifier les quotas dans le déploiement, sans faire confiance aux en-têtes de transfert fournis par le client.

Proxy, démarrage et secrets

Le proxy accepte uniquement les chemins /_matrix/client/… et /_matrix/media/…. Sa destination vient de MATRIX_UPSTREAM ; un client ne choisit jamais un hôte amont. Les chemins de traversée encodés sont refusés. Les identifiants encodés valides sont transmis sans réécriture. Seuls Authorization et Content-Type sont transmis comme en-têtes de requête. Les cookies et en-têtes de transfert sont exclus. Les redirections sont interdites.

PUBLIC_ORIGIN est une origine HTTPS seule, sans identifiants, chemin, paramètre ni fragment. HTTP est accepté pour localhost, 127.0.0.1 et ::1 en développement. Le point d’entrée refuse une écoute réseau en clair ; une exposition distante exige un reverse proxy TLS réellement configuré. L’application seule ne vérifie pas le certificat ni la configuration TLS de ce proxy.

npm run setup crée un .env local ignoré par Git, avec trois valeurs aléatoires indépendantes de 256 bits : service de politiques, inscription Synapse et code d’inscription. Le fichier est créé exclusivement : un fichier ou un lien existant reste intact. Aucune valeur secrète n’est affichée. Sous POSIX, le mode demandé est 0600 ; sous Windows, les droits dépendent des ACL du répertoire local. Le module exporte aussi setup({directory}) sans effet de bord à l’import, pour l’outillage d’installation.

Le mot de passe et les jetons ne sont pas journalisés par ce code. Le mécanisme d’inscription partagée utilise HMAC-SHA1 uniquement pour le protocole imposé par Synapse ; le serveur Polytalk ne stocke pas de mot de passe. Configurer les mêmes secrets dans les composants de confiance avant l’ouverture du service.

Cette vérification couvre les comportements testés de ce serveur. Elle ne remplace ni un test d’intrusion, ni une qualification TLS, ni les tests d’échanges chiffrés réels de la pile Matrix.
